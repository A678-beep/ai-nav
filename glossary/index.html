基础（27）

大语言模型

用海量文本训练、以预测下一个词为核心任务的大型神经网络，具备理解与生成自然语言的能力；常见用法是接入客服机器人自动撰写回复。

Token

模型处理文本的最小单位，一个汉字、词片段或标点都可能算一个，模型按它计数并计费；调用 API 前可用分词工具估算输入长度与成本。

上下文窗口

模型单次请求中能同时读到的 Token 总量上限，包含提示词、对话历史和待生成内容；处理长合同或长文档问答时需确认它是否放得下。

温度

控制模型输出随机性的参数，值越低结果越确定、越高越发散；写严谨的产品说明时调低，头脑风暴广告文案时调高，并配合 Top-p 一起用。

Top-p

一种采样策略，只从累计概率达到设定值的那部分候选词中抽取，从而限制可选范围；与温度配合，可在创意写作中保留变化又避免离谱用词。

提示词

用户发给模型的指令与素材，决定任务目标、输出格式和可用信息；把需求、示例和限制写清楚的提示词，能显著提升客服话术或周报生成的质量。

系统提示词

在对话开始前设定模型身份、语气和边界的指令，优先级高于普通用户输入；产品上线时用它固定助手人设，并约束其不得回答的范围和敏感话题。

少样本学习

在提示词中给出几个输入输出示例，让模型模仿样式完成同类新任务，无需更新模型参数；适合快速统一分类标签、抽取字段或文案风格，比微调更轻便。

思维链

引导模型先写出中间推理步骤再给出结论的提示方法，能改善多步计算和逻辑题表现；做数学解题、数据核对或复杂排期时可要求它逐步分析，便于检查错在哪一步。

幻觉

模型生成看似合理却与事实不符或凭空捏造的内容，常出现在引用、数字和细节上；用于法律、医疗或财务问答时必须人工核对来源，并用检索结果佐证。

微调

用自有标注数据继续训练已预训练的模型，调整部分或全部参数，使其更贴合特定任务或风格；企业可用历史工单微调出更懂内部术语的客服模型，但成本高于提示工程。

LoRA

一种低秩适配的微调方法，冻结原模型、只训练少量附加参数就能改变模型行为，显存占用低、便于切换；适合为不同客户分别维护轻量定制模型或画风。

RAG 检索增强

先从外部知识库检索与问题相关的片段，再把片段放进提示词让模型据此作答，可减少幻觉并保持信息更新；常用于企业内部文档问答和客服支持。

向量数据库

专门存储和检索向量表示的数据系统，按语义相似度而非关键词匹配查找内容，支持大规模近邻搜索；为客服知识库提供按意思召回文档的能力，也用于推荐和去重。

嵌入

把文本、图片等转换成数值向量的过程或结果，语义相近的内容在向量空间里距离更近；常用于语义搜索、文本聚类和推荐系统，也是 RAG 检索的基础。

知识库

整理好的结构化或非结构化资料集合，供检索或模型引用，是 RAG 的事实来源；把产品手册放进去，问答助手便能回答具体参数，并随文档更新同步调整。

智能体

能自主拆解目标、调用工具并根据执行结果继续行动的程序，通常由大模型驱动决策；可让其在浏览器里完成比价、填表、订票等多步任务，失败时还能重试。

工具调用

模型按约定格式输出函数名和参数，由外部程序执行后把结果返回给模型、再继续生成回答的机制；让助手查天气、下单、读数据库或发邮件都依赖它。

MoE 混合专家

由多个专家子网络加一个路由网络组成的模型结构，推理时每次只激活少数专家，兼顾参数容量与计算成本；适合在有限算力下扩展大模型规模。

量化

用更低精度（如 8 位或 4 位整数）表示模型权重，减少显存占用并加快推理；把大模型部署到消费级显卡或边缘设备时常做量化。

知识蒸馏

先用大模型（教师）的输出作为监督信号训练小模型（学生），让小模型达到接近的效果却更轻量；适合把能力迁移到手机端或高并发接口，降低部署成本。

RLHF 人类反馈强化学习

先让人对模型的不同回答排序，训练奖励模型，再用强化学习优化生成策略，使输出更符合人类偏好；常用于让助手回答更安全、更有帮助，也用于对齐风格。

多模态

模型能同时处理文本、图像、音频、视频等一种以上输入或输出形式，并在不同模态间建立关联；可上传商品图让助手识别款式并生成上架描述，也能看图回答问题。

推理模型

在回答前先进行较长内部思考、擅长数学与多步逻辑任务的模型类别，通常响应更慢、成本更高；适合代码调试、复杂规划、数据分析等需要严谨推导的场景。

上下文缓存

把重复出现的提示词前缀或长文档的中间计算结果缓存起来，后续请求直接复用，从而降低延迟和费用；适合固定系统提示加多轮追问的客服或知识问答产品。

提示词注入

攻击者在输入内容里夹带指令，诱使模型忽略原有规则、泄露信息或执行越权操作。接入外部网页、文档与用户输入时，需要做内容隔离、权限限制与输出过滤。

越狱

用诱导性话术绕过模型的安全对齐，使其输出本应拒绝的内容。防护主要靠安全过滤、指令约束与红队测试，单靠一条提示词或一次拒答往往拦不住。

图像（14）

扩散模型

通过逐步去噪从随机噪声生成图像的模型，训练时学习把加噪过程倒过来；是文生图、图像修复、超分辨率等工具的核心，生成质量取决于训练数据和采样设置。

潜空间

模型（如自编码器）把数据压缩后得到的低维表示空间，图像扩散模型常在此空间去噪，而非直接在高维像素上计算，从而节省算力；文生图工具借此加快出图。

采样步数

扩散模型生成图像时去噪迭代的次数，步数越多通常细节越充分但耗时更长，过少则画面粗糙；出图时需按速度与质量权衡调整，也可配合更快的采样器减少步数。

CFG Scale

无分类器引导系数，用于控制生成结果对提示词的贴合强度，值过高易出现僵硬或过饱和，过低则偏离描述；调参时可从中间值试起，再按画面效果微调。

种子

生成模型采样时决定随机数序列的初始值，固定种子可在相同提示词和参数下复现近似结果；做系列配图或排查问题时用它保持可比性，换种子则会带来新变化。

ControlNet

给扩散模型添加空间控制条件的附加网络，可用边缘、姿态或深度图约束生成结构。适合固定人物姿势、复刻线稿布局或控制建筑透视，让构图从靠抽卡变为可精确复现。

IP-Adapter

一种轻量适配器，把参考图的风格或人物特征注入文生图模型，无需额外训练即可复用。常用来统一角色形象，或让整套物料保持同一种视觉风格，便于批量出图。

重绘强度

图生图时的去噪强度参数，决定保留原图多少信息：数值越低越接近原图，越高改动越大。低值适合微调配色与光影，高值适合大幅重构画面或彻底更换风格。

VAE

变分自编码器，在扩散模型里负责把图像压缩到潜空间，生成后再解码回像素图。版本与底模不匹配时结果会发灰或偏色，更换模型时需成对检查并固定版本。

图生图

以参考图为起点，在潜空间加噪后重新去噪，得到构图相近的新图。常用于草图细化、风格转换，或在不改变主体结构的前提下更换背景与光影，比纯文生图更可控。

局部重绘

只对蒙版选中的区域重新生成，蒙版外像素保持不变。适合给照片换衣服、去除瑕疵或替换画面中的物件，改动范围可控，比整图重画更省算力，也更容易保留原图质感。

放大修复

用超分辨率模型提升图像分辨率并补回细节，同时抑制噪点与模糊。适合把生成的小图放大为印刷、大屏或电商详情页可用的高清素材，避免直接拉伸导致糊边。

蒙版

标记编辑范围的二值或灰度图，白色区域参与生成，黑色区域保留原样。局部重绘、扩图与图像合成都靠它划定作用区域，边界越准，生成结果与原图的衔接越自然。

风格参考

提供一张样例图，让模型提取其中的色彩、笔触与光影气质再用于新内容。适合让一批配图或整站视觉保持统一调性，而不必逐张写很长的提示词，也便于批量复用。

视频音频（9）

关键帧

动画或视频中定义动作起止的关键画面，中间帧由插值或模型补出。适合先摆好几个关键姿势，再交给工具生成连贯的过渡动作与运镜，省去逐帧绘制。

首尾帧

图生视频时指定第一帧与最后一帧的用法，由模型补出中间的运动过程。适合做转场、变身特效或起止构图固定的产品短片，结果比纯文字提示更可控。

运镜

对镜头运动的描述与控制，如推近、拉远、环绕、摇移。写提示词时明确运镜方向与幅度，能让生成视频更有电影感与空间层次，也更接近分镜意图，减少反复抽卡。

帧率

每秒显示的静态图像帧数，是衡量视频流畅程度的基本指标。帧率越高画面越顺滑，但渲染时间、算力与文件体积也越大，生成前需按用途选定档位。

码率

单位时间内传输或存储的视频数据量，直接决定清晰度与文件体积。同分辨率下码率越高细节保留越多，但存储与带宽成本也越大，需按发布平台的要求权衡。

口型对齐

让生成人物的嘴型与配音音轨在时间上同步的技术，需同时对齐发音口型与节奏。做数字人播报、外语配音或虚拟主播时用它，可避免声画错位带来的违和感。

TTS 语音合成

把文本转成自然语音的技术，可调节语速、停顿与情绪，部分工具支持多语言与指定音色。适合给短视频配音、制作有声内容，或为应用加上朗读与播报功能。

ASR 语音识别

把语音转写成文字的技术，是会议记录与语音指令的基础。适合做字幕生成、访谈整理、语音输入与客服质检等场景，常与说话人分离、标点恢复等步骤配合使用。

音色克隆

用少量参考音频学习说话人的音色特征，再用它合成任意新语音，输出可与原声高度相似。适合为品牌统一配音，或让虚拟角色在多次生成中保持固定的声音。

编程（7）

代码补全

编辑器根据上下文预测并续写代码片段的能力，能给出单行或整段建议，按键即可采纳。写样板逻辑、补全函数参数与重复结构时最省事，也明显减少了查文档的次数。

代码索引

把代码库解析成可检索的结构，让 AI 理解跨文件的函数、类与引用关系。仓库越大，基于索引的检索越比全文搜索准确，也越节省上下文窗口，是长项目问答的基础。

Agentic 编码

让 AI 代理自主读写文件、运行命令、验证结果并循环修正，而不只是补全单行代码。适合完成跨文件的改造、迁移与缺陷修复等需要多步执行的任务，人主要做目标设定与结果验收。

沙箱

隔离运行代码的环境，限制文件、网络与系统权限，避免未知代码伤及主机。跑 AI 生成的脚本、做在线评测或演示时基本都要用到它，也是代理写代码的安全前提。

Pull Request

把分支改动提交合入主干前的评审请求，包含代码差异、讨论与自动化检查结果。团队协作时用它让 AI 产出的代码先过审再合并，责任划分与回滚都更清晰。

单元测试

针对函数或模块的最小可测单元编写的自动化测试，校验输入输出是否符合预期。让 AI 改完代码后跑一遍，能快速发现回归，避免修一处却弄坏另一处，是验收改动的低成本手段。

代码覆盖率

测试执行时被覆盖到的代码比例，常见行覆盖与分支覆盖等口径。它只说明代码有没有被跑到，不能证明逻辑正确，需结合用例质量与实际场景一起判断。

工具（3）

工作流自动化

把多个步骤按触发器与条件串成自动执行的流程，例如收到表单后自动生成回复并归档。适合替代重复的手工操作，减少遗漏与等待，复杂流程应保留人工复核节点。

Webhook

事件发生时由服务主动向指定 URL 推送数据的回调机制，无需反复轮询。适合把 AI 处理结果实时同步到其他系统、通知群聊，或作为下一步流程的触发条件。

OCR

光学字符识别，把图片或扫描件中的文字转成可编辑文本。适合批量录入发票、合同与截图，再交给模型做摘要、审核或结构化字段抽取，准确率受清晰度影响较大。
