PDF 加密 工具：算法、权限与批量加密脚本

实用工具·更新于 2026-11-15·PDF 加密 工具, PDF 打开密码, PDF 权限密码, PDF 算法, PDF 批量加密, PDF 权限设置

给一家律所整理 260 份劳动合同 PDF，交付 HR 系统时要求只能看不能改、禁止打印，外部供应商那批还得加打开密码。用 qpdf 一条命令加权限，260 份 90 秒跑完。PDF 加密 工具 分两类：设打开密码的，和只设权限的，选错会出现「能打开但限制全失效」的情况。

一、打开密码与权限密码，先分清防谁

打开密码（user password）打开时就要输，AES-256 下没有密码基本没救；权限密码（owner password）只限制打印、复制、编辑，很多阅读器根本不理。Chrome 内置阅读器、WPS 对只设权限的 PDF 照常打印，真正保密必须设打开密码。算法只看 AES：RC4 在 PDF 2.0 里已弃用，AES-128 从 PDF 1.6 起支持，AES-256 要 PDF 2.0 或 Acrobat X 以上。qpdf 的 --encrypt 指定 256 就是 256 位 AES，2010 年前的 ERP 和部分老 OA 可能只认 RC4，批量前先拿一份样本试打开。权限颗粒度有五项：print、modify、extract、annotate、form，qpdf 里对应 --print=none、--modify=none、--extract=n。避坑一，只设权限密码等于没设，截图和打印都拦不住；避坑二，中文密码在旧版 Foxit 上会直接报错，统一用 ASCII 密码。

二、PDF 加密 工具 怎么选：命令行、Acrobat 与自部署

广告位（文章中部）AdSense / 广告联盟代码插入点 · 建议 728×90 / 移动端 320×100

批量我全用 qpdf，命令是 qpdf --encrypt "读密码" "所有者密码" 256 --print=none --modify=none --extract=n -- in.pdf out.pdf，外层 PowerShell 遍历文件夹，脚本读一份 CSV（文件名、密码、权限档位）拼参数。260 份平均每份 0.3 秒，90 秒出完；Acrobat Pro 手动一份约 40 秒，260 份得三个多小时。Acrobat 的路径是「工具—保护—加密—使用密码加密」，勾选限制编辑和打印，适合零星几份。PDF24 Creator 免费，拖进列表就能加密，没有命令行。涉密文件用 Stirling PDF 自部署，docker 起在内网 8080，文件不出局域网。PDF 批量加密 跑完必须用 qpdf --show-encryption 抽查，看 R = 6（AES-256）和 P 值权限位对不对。避坑三，密码明文写进脚本再提交 Git 等于公开，用环境变量或交互输入；避坑四，8 位纯数字密码在消费级显卡上几分钟跑完字典，交付密码至少 16 位，大小写加符号。

三、260 份合同的批量流程与两个坑

那 260 份分三档：在职员工可打印、禁修改；离职证明禁打印；外部供应商加 16 位打开密码。脚本按文件名后缀匹配档位，跑完输出报告，逐份记录权限、算法和耗时。第一轮抽检 20 份，有 3 份仍能打印，原因是重复加密时 qpdf 报错、脚本没退出就跳过了，加了错误捕获和二次校验才干净。PDF 权限设置 别指望防截屏，它只挡打印和编辑；要防转发就设打开密码，密码单独走短信或电话，别和 PDF 放同一封邮件。避坑五，加密前把源文件留一份在离线盘，qpdf 没有找回密码的后门，忘了就是重做。避坑六，加密只改对象头，体积几乎不变，别按体积判断有没有加密，看 --show-encryption 的 R 值才准。

总结

PDF 加密 工具 的选型顺序是：先分打开密码和权限密码，再用 qpdf 批量加 AES-256 权限，零星几份交给 Acrobat 或 PDF24，涉密走自部署。PDF 批量加密 和 PDF 权限设置 都写进 CSV 加脚本，260 份 90 秒跑完，抽检看 R = 6 这一行，比手工点 260 次可靠。
