Copilot 无法 登录：代理与账号权限

编程助手·更新于 2026-11-15·Copilot 无法 登录, GitHub Copilot 登录, 代理设置, 企业策略, Copilot 插件 登录 失败, GitHub Copilot 授权 失败

换新笔记本那天，VS Code 里点 Sign in to GitHub，浏览器授权页转两圈弹回来，右下角还是未登录，输出面板里一行 FetchError，连 api.github.com 超时。Copilot 无法 登录 的坑我前后踩过四回，代理、账号、插件、企业策略各占一次，顺序错了就会一直在重装扩展。

先看它卡在哪一步

Copilot 无法 登录 卡在哪，打开输出面板就有答案。登录分三段：编辑器拉起浏览器、GitHub 授权回跳、扩展拿 token 请求接口。点下去没反应，多是浏览器没弹出来，命令面板里再跑一次 GitHub Copilot: Sign In，顺便看默认浏览器有没有被拦。浏览器回来了、状态栏还是未登录，就把输出面板的通道切到 GitHub Copilot，日志会直接写是 connect ETIMEDOUT 443 还是 403，前者是网络后者是权限。我有一次折腾两小时不停重装，其实日志第一行就写着 Timed out waiting for authentication provider to register，说明它连 VS Code 的授权回调都没等到。Copilot 插件 登录 失败 的日志只有两三行，但足够把范围缩掉一半。

代理和证书：VS Code 不读系统代理

广告位（文章中部）AdSense / 广告联盟代码插入点 · 建议 728×90 / 移动端 320×100

系统代理开着不等于 VS Code 走代理。设置里搜 proxy，把 http.proxy 填成 127.0.0.1:7890 这种 http 协议地址，只认 http 开头，写 socks5 会直接失败，这是我第一个坑；填完还得 Developer: Reload Window 才生效。VS Code 的 http.proxy 同时管 https 请求，不用再单独配一份。公司网关用自签证书的，日志里是 self signed certificate in certificate chain，临时把 http.proxyStrictSSL 关掉能通，正规做法是把根证书装进系统信任，再给终端设 NODE_EXTRA_CA_CERTS 指向证书文件。代理配错时，浏览器那一步授权能过，回调却回不到 VS Code，表现出来就是 GitHub Copilot 授权 失败，所以先修网络再查账号，顺序反了会把两小时全花在权限页上。还有一个坑更常见：代理关了忘了删 http.proxy，之后一直是 ETIMEDOUT，我把这一行写进项目 README 才没再犯。

账号、企业策略和插件版本

GitHub Copilot 授权 失败 的第二种情况在账号。先到 GitHub 账号设置里的 Copilot 订阅页看套餐，Copilot Free 每月 2000 次补全加 50 次对话，个人够用；学生和教师要在账号里做认证；组织成员要等管理员分配 seat。组织开了 SAML SSO 的，还得在设置的应用授权里给 GitHub for VS Code 授权，并对组织点 Grant，不做这一步授权能过、接口一律 403。企业管理员把 Copilot 的 IDE 使用关了，会直接提示被组织禁用，只能找管理员开，生效要等几分钟。插件本身也查：GitHub Copilot 和 Copilot Chat 两个扩展版本要一起升，VS Code 太旧会激活失败；左下角 Accounts 里如果登的是另一个 GitHub 账号，会出现有订阅却没权限的假象。我们同事那次 Copilot 无法 登录 卡了一下午，最后是组织 seat 没分，管理员勾选后五分钟恢复；这类 Copilot 插件 登录 失败 后台一眼看得出，前台只会转圈。

总结

现在我的顺序固定：先看输出面板，确认卡在网络、权限还是插件，再修代理和证书，然后核对订阅、SSO 和 seat，最后才重装扩展。Copilot 无法 登录 九成不是扩展坏了，是网络或权限没打通。
