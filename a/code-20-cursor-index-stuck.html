Cursor 索引 卡住：先查目录再重建

编程助手·更新于 2026-11-15·Cursor 索引 卡住, Cursor 代码库 索引, Cursor 排除目录, Cursor 索引 缓存, Cursor 索引 一直 转圈, Cursor 重建索引 失败

接手一个 2019 年的中台仓库，Cursor 打开后右下角一直显示 Indexing，进度卡在 37% 不动，用 @Codebase 问自己刚写的函数，回的是 No results。同一个仓库换回 VS Code 一切正常，问题只出在索引这一层。Cursor 索引 卡住 的样子都差不多：文件太多、目录没排干净，或者旧索引一直没清。

先量体积：索引到底在扫什么

排查第一步不是重启，是量体积。Cursor Settings 里翻到 Indexing & Docs（旧版叫 Features → Codebase Indexing），Cursor 代码库 索引 的状态、Indexed files 数字和进度条都在这；再开 View → Output，下拉框选 Cursor Indexing & Retrieval，日志会写清停在哪个目录、哪个 chunk 上。我那个仓库 Git 里 2.1 万个文件，目录里实际有 38 万个：node_modules 一个目录占 31 万，dist 和 coverage 又占 4 万，还有个 20 万行的生成文件。Cursor 默认会忽略 node_modules、.venv、.next 和锁文件，可这份工程把依赖目录改名成 vendor 提交进仓库，绕开了默认规则。文件数从 38 万降到 2.1 万，索引从卡 4 小时变成 6 分钟跑完，@Codebase 也能搜到自己写的函数。文件过 10 万、或索引期间内存涨到 3GB 以上，基本都停在 30% 到 60%，不是等你，是在空转。Cursor 索引 一直 转圈 的时候，先数文件再谈别的。

排除目录，再按顺序重建

Cursor 排除目录 只认仓库根目录的 .cursorignore，语法和 .gitignore 一样：vendor/、dist/、coverage/、*.min.js、*.map、**/generated。容易搞混的是：.cursorignore 连 Agent 和 Tab 的读取一起挡，想只挡索引、保留 @ 引用能力，就写 .cursorindexingignore，Cursor 照常能手动引用，只是不进语义索引。想清 Cursor 索引 缓存，正确顺序是：Cursor Settings → Indexing & Docs 点 Delete Index，彻底退出 Cursor（任务管理器确认 Cursor.exe 结束），重开仓库点 Sync 重建。旧索引没删就重建，等于在坏数据上叠新数据，Cursor 重建索引 失败 十次有八次是这个原因。日志里 Handshake failed 是服务端故障，等会儿再试；2.1.47 到 2.1.49 这几个版本有过索引无限循环的 bug，升到新版能少踩。网络差时在 settings.json 里加 cursor.general.disableHttp2 会稳一些。

一次恢复记录和两个坑

上周那个仓库恢复过程：先 Delete Index，再把 .cursorignore 里误加的 src/ 删掉，之前图快把源码也排了，AI 连业务代码都看不到；重建后 Indexed files 停在 20,913，状态变成 Indexed。第一个坑是把 .cursorignore 当性能开关，排掉 src、packages 这种真要问的目录，索引快了，可用性报废，性能只该排生成物。第二个坑是索引没跑完就提问，@Codebase 未完成时常返回 No results，容易误判功能坏了，先看状态栏。还有个小细节：仓库放在 OneDrive 同步目录，文件一动就触发重新索引；挪到本地磁盘，重建时间少一半。重启后还是 Cursor 索引 一直 转圈，就再翻一次 Output 日志。有人问 Cursor 索引 卡住 怎么解决，我的顺序永远是先看日志、再排目录、最后重建。

总结

Cursor 索引 卡住 多数不是软件坏了，是索引范围失控：先看 Output 日志和文件数，用 .cursorignore 或 .cursorindexingignore 挡掉生成目录，再按 Delete Index、重启、Sync 的顺序重建。38 万文件缩到 2.1 万、4 小时变 6 分钟，收益比换电脑实在。真遇到 Cursor 索引 卡住 怎么解决，先量体积再动手；Cursor 重建索引 失败 也多半是旧索引没清，顺序别做反。
