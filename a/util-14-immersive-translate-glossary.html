沉浸式翻译 术语库：35 条术语统一译名

实用工具·更新于 2026-11-15·沉浸式翻译 术语库, 沉浸式翻译 术语表, 术语库 导入, 沉浸式翻译 术语 不生效, 沉浸式翻译 术语表 怎么用

一份 30 页的开源推理框架文档，第一版翻完，agent、token、checkpoint 三个词前后出现了七种译名，读者在评论区问 agent 到底是不是代理。我建了一份 35 条的沉浸式翻译 术语库，第二版通读只找出两处不一致，用的还是同一批模型。这篇写库怎么建、怎么导入、以及你建的库为什么不生效。

一、先开内置领域库，再谈自建

打开插件面板，点「设置」，左侧找「AI 术语库」，内置的编程、法律、医学几个领域先按需打开。内置库覆盖通用词，内部 API 名、产品名、项目代号这些必须自建。

我的判断标准：一个词在文档里出现超过 5 次、译错会影响理解，就进库。35 条里 agent 固定成「智能体」、token 固定成「词元」、checkpoint 固定成「检查点」，这三条占了全文出现次数的一半，改完整篇读感就顺了。术语库对所有翻译引擎生效，优先级高于模型判断，所以它能统一译名，也能把一条错译铺满全文。

二、CSV 三列，编码别错

广告位（文章中部）AdSense / 广告联盟代码插入点 · 建议 728×90 / 移动端 320×100

沉浸式翻译 术语库 的自建库用 CSV，三列：原文、译文、备注，第一行写表头。导入路径是设置 → AI 术语库 → 自建术语库 → 导入，选中小文件 2 秒生效。两个细节：文件要 UTF-8，存成 GBK 导进去中文全是乱码；译文里带逗号或引号要整格用双引号包起来，否则列会错位。

我第一版 35 条里有 4 条备注写了逗号没加引号，导入后整行串位，排查了半天。长术语优先写整条，比如 KV Cache 整条进库，别拆成 KV 和 Cache，模型认整词比认组合准。沉浸式翻译 术语表 怎么用 这个问题，答案就是先导 10 条小批量试效果，别一上来导几千条。

三、不生效和译得太硬

最常见的不生效原因是大小写和空格：库里写 Agent，原文是 agent 就匹配不到；库里多打一个尾随空格，同样匹配不到。我统一把小写形式写进原文列，正文里大写小写都能命中。

第二个坑是术语太长太书面，把 prompt 硬译成「提示指令文本」，句子又长又硬，我的译法是「提示词」，短词优先。第三个坑是沉浸式翻译 术语库 压过上下文：词锁死之后模型不再按语境变通，遇到 token 过期这种技术语境，词元就比令牌别扭，所以我只锁真正要统一的词，一次控制在 50 条以内。沉浸式翻译 术语 不生效 时，先搜标题和正文里的写法，九成是写法不一致，不是工具坏了。

总结

术语库不是越大越好，30 到 50 条覆盖高频词就够，剩下的交给模型。顺序是开内置领域库、CSV 三列导入、小批量验证、按写法排错。沉浸式翻译 术语表 怎么用 走一遍就明白：真正花时间的不是翻译，是发现三个词有七种译名的那一遍通读。沉浸式翻译 术语 不生效 时别急着换引擎，先对数一遍写法。
