文件 去重 工具：哈希、保留规则与批量清理

实用工具·更新于 2026-11-15·文件 去重 工具, 重复文件检测, 哈希去重, 重复文件清理, 重复文件检测工具, 文件去重保留规则

帮朋友收拾一台用了八年的素材机，4TB 机械盘加 2TB 移动硬盘，一共 186 万个文件。扫完他自己都不信：完全重复的文件 41 万个，合计 312GB，够再买半块盘。文件 去重 工具 不是点一下全删，顺序错一次，唯一那份就没了，我按三层哈希、四条保留规则、先移后删走完，一个有效文件没丢。

一、哈希分三层，别一上来就算全量

直接给 186 万文件算全量哈希，机械盘实测读速 160MB/s，跑到天亮也跑不完。实际做法是三层：第一层比大小，121 万个文件的大小是独一份，直接排除；第二层对剩余文件读头尾各 4KB 和中段 4KB，只剩 29 万个；第三层才对这些算全文件哈希，合计 480GB，一个多小时出结果，整轮两小时出头。顺序反了，七个小时都不一定够。哈希选 blake3 或 xxhash，比 md5 快两三倍，本地整理没有防篡改需求，不必上 sha256。命令行 rmlint 默认就是这种大小加首尾字节的快速模式，结果不放心再加 -P 做逐字节比对，代价是时间翻几倍。

重复文件检测工具 里，我给普通同事装 Czkawka，Rust 写的，扫 186 万个文件的元数据四分钟，结果按哈希分好组，删之前能展开核对、能导出清单。dupeGuru 的强项是图片和音乐，图片模式按画面内容和颜色做模糊匹配，同一张照片被压过两次、EXIF 不一样也认得出，整理手机相册比全文件哈希实用。要接脚本上 fclones 或 rmlint，能导出 JSON，也能把重复的那份换成硬链接。群晖的 Btrfs 去重只对共享文件夹生效，Windows Server 按卷开，开了以后写入变慢，个人电脑上别指望。文件 去重 工具 选型看两件事：能不能导出待删清单、能不能排除目录。

三、保留规则先写死，删除先移后删

文件去重保留规则 我定四条：保留路径最深的一份，它旁边有工程文件能对上；照片留原始尺寸和拍摄时间，微信压缩版、缩略图优先清；同名不同内容的永不自动删，交人工判断；系统目录、云同步目录、Git 仓库、在用的项目目录整目录排除。删除不点删除，先移到「待删」文件夹放两周，没软件报错再清空。云同步目录最险，这台删了那台跟着删，回收站不一定够用。硬链接也容易误判，两个路径指同一份数据，删一个不释放空间，看着腾了 300G 实际一点没少，要用 TreeSize 看物理占用。这轮 41 万个重复里删掉 38 万个，留 3 万个走人工，腾出 296GB。

总结

文件 去重 工具 省的不是点删除的时间，是判断哪份能删的时间。三层哈希把七小时压到两小时，保留规则先定死，删除统一先移后删。重复文件检测工具 挑顺手的就行，真正防丢的是那份排除清单；文件去重保留规则 写得越细，按确定键的时候越不慌。
