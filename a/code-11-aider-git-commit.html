Aider git 提交：自动提交该不该

编程助手·更新于 2026-11-15·Aider git 提交, Aider 自动提交, Aider 配置, Aider 自动提交 关闭, Aider 提交信息 自定义

第一次用 Aider，我盯着终端看它每改一个文件就自己 git commit 一次，半小时仓库里多了 17 个 commit，提交信息全是英文一句话。一开始觉得省事，第三天回滚一个改动时才发现历史被切得太碎，找不回“改之前能跑”的那个点。Aider 的自动提交是设计特性，不是 bug，问题在于大多数人没配 dirty-commits。这篇写我怎么判断 Aider git 提交 该自动还是手动。

默认行为与常用配置

Aider 默认每轮编辑后自动提交，提交信息由它生成。安装是 pip install aider-chat，启动 aider --model deepseek/deepseek-chat，用 /add src/order.py 指定文件，/diff 看改动，/undo 撤回上一轮。Aider 还有 /git 命令能看仓库状态，改文件前先跑一次，确认工作区是干净的。要关自动提交，启动加 --no-auto-commits，或者写进 ~/.aider.conf.yml：

yaml
auto-commits: false
dirty-commits: false
commit-prompt: "用中文写一行 conventional commit，不超过 50 字"

dirty-commits: false 很关键，它保证工作区有未提交改动时 Aider 不硬提交，避免把别人的改动卷进你的 commit。Aider 配置 里这两行，是我踩过坑之后加的。

什么时候开，什么时候关

重构和调试阶段我关掉自动提交，改成每验证一步手动 /commit；写新功能时开着，因为小步提交正好符合我的节奏。判断标准只有一条：我能不能在一次提交的粒度内跑通测试。能，就自动；不能，就手动。第一次把 Aider 自动提交 关闭 时我还有点担心，跑了一周发现手动反而更可控。Aider 提交信息 自定义 之前，先想清楚 Aider 自动提交 关闭 之后谁决定提交时机，Aider git 提交 的节奏就是你的 review 节奏。关掉自动提交后，git log 干净很多，回滚也方便。我在每轮结束时会集中看一遍 diff，确认没有顺手改的无关文件。Aider 提交信息 自定义 成中文挺好用，但别超过 50 字，超过之后 git log 一行显示不全。

一天下来手动模式大约 6 到 8 个 commit，自动模式是 20 个往上，差别不在数量，在可读性。开了自动提交也别让它在同一文件上连改五轮，五轮就是五个 commit，中间态没法用，我一般一轮只提一个文件。

三个坑

一是自动提交会把未完成代码写进历史，中断后你再回来，分不清哪个 commit 是半成品。二是 Aider 只提交它改过的文件，但如果你之前有未提交改动，容易和它的改动混在一起，dirty-commits: false 能挡一部分。三是提交信息默认英文，团队要求中文规范就提前配置，否则事后再改一遍很痛苦。

另外大仓库开 repo map 会消耗不少 token，DeepSeek 一轮大约几毛钱，但长会话累积起来也不少；Aider 的 /tokens 能看当前用量。token 成本也要算：repo map 默认打开，大仓库一轮 4 万 token 起步，--map-tokens 1024 能压下来。提交信息模板我固定带模块名，比如 feat(order): 支持批量取消，回看时一眼认范围。

总结

Aider git 提交 的取舍标准很简单：能一次跑通测试就自动，跑不通就手动。把 auto-commits 和 dirty-commits 写进配置文件，比每次命令行加参数可靠。历史干净，回滚才有意义。Aider 自动提交 不是不能用，是要知道什么时候不该用。
