前端 页面 生成：提示词、组件和验收三步

编程助手·更新于 2026-11-15·前端 页面 生成, 页面 生成 提示词, 组件 拆分, 页面 验收, 前端 页面 生成 提示词, AI 生成 前端页面 怎么验收

上周接了个后台权限配置页，两张 Figma 稿，排期两天。用 AI 生成前端页面，我 40 分钟拿到第一版，贴进项目就翻车：颜色写死成 #1890ff、组件切得比米粒还碎、接口字段名靠猜。前端 页面 生成 快不快看模型，能不能用看你把需求拆到多细。

提示词写满 400 字，别只丢一句“帮我写个页面”

我的模板四段：技术栈写死（React 18.2、TypeScript 5.4、Ant Design 5.12、CSS Modules）；页面结构列全（搜索栏、表格、分页、抽屉表单）；状态补齐（loading、空数据、接口 500、无权限）；禁止项单独一段（不加新依赖、不写死颜色、mock 数据放 mock.ts、文案走常量）。前端 页面 生成 提示词 里最值钱的就是禁止项，不写它一定给你内联样式和随机色值。提示词里再给一两个真实字段名（比如 permCode、roleId），比写“按接口来”强，模型会照着编字段。附一张手绘线框图比纯文字稳，我做过 10 次对比，结构偏差从 4 次降到 1 次。一个坑：别一个提示词要 5 个页面，第 3 个开始复用错组件、样式串味，单页单轮。

先让它出组件树，再逐组件写代码

广告位（文章中部）AdSense / 广告联盟代码插入点 · 建议 728×90 / 移动端 320×100

第二轮只要组件树：Page → FilterBar → DataTable → EditDrawer → StatusTag，每个标清楚哪些用项目里现成的（src/components/Table、Form），哪些新建。审完树再逐组件生成，拆完先跑一遍类型检查，单组件阶段改类型比整页拼完再查省一半时间，单文件超过 200 行就打回拆；我见过一次生成 600 行的 index.tsx，改一个字段翻了 3 分钟。命名跟项目走，样式只用 CSS 变量，新颜色必须来自设计 token。AI 生成前端组件 最容易丢的是复用约束，前端 页面 生成 提示词 里得点名现有组件路径。

验收只看四个硬指标

AI 生成 前端页面 怎么验收，我的清单：tsc --noEmit 零报错、ESLint 零 warning、接口字段和 openapi 生成的类型对得上、首屏 3 秒内可交互且 console 无红色报错。再加一条人工点验：空数据、超长文本、无权限三个状态各点一遍，别只看正常流程。案例是权限配置页，AI 版 380 行、6 个组件，我改了 40 分钟：3 处硬编码颜色、2 处接口字段名错、1 处空状态没写；提测后发现 2 个 bug，手写版当时是 1 个。两个坑：别让 AI 重写项目已有的 Button 和 Table，重复组件半年后没人敢删；也别接受它自造的请求函数，统一走项目的 request 封装。验收结果写进 PR 模板，谁改的页面谁补清单，提测前少一轮返工。

总结

三步走：提示词 400 字写死技术栈和禁止项，组件树先审后写，四指标验收。适合列表、表单、详情、配置这类中后台页面，不适合动画多、强拖拽、实时协作的页面，三类我都试过，改的时间比自己写还长。AI 生成 前端页面 怎么验收 这件事，核心是把它当一个手艺一般的新人：交得快，但每个边界状态都得你自己点一遍。三个数记住：提示词 400 字、单文件 200 行、验收 40 分钟。
