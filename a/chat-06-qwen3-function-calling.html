通义千问 Qwen3 函数调用调试笔记

对话AI·更新于 2026-11-15·通义千问 Qwen3, 函数调用, 工具调用, Qwen3 函数调用, 工具调用 JSON Schema

上周我用通义千问 Qwen3 做一个小助手，功能只有两个：查天气、查快递。第一版死活不触发函数调用，模型在思考块里自问自答，接口返回里一个工具调用都没有。折腾两天后跑通，发现坑全在 JSON Schema 和思考模式上，跟模型能力关系不大。这篇记录 Qwen3 函数调用调通的全过程，按顺序照做能少走两天弯路。

先关掉思考模式再调工具

Qwen3 是混合思考模型，开思考时它会在推理段里预演一遍调用流程，真正返回的工具调用反而被吞掉。我的做法是三步：第一步用非思考模式跑通链路，请求里传 enable_thinking 为 false 或降低思考预算；第二步温度先设 0.6，工具调用场景别用 1.0 那种发散参数；第三步给每个工具写清楚三行描述，说明什么时候用、参数从哪来、返回什么。链路通了再开思考模式，只用于复杂查询。二十次测试里，非思考模式触发率 95%，开思考模式反而掉到 70%。Qwen3 函数调用的第一课不是写提示词，是把思考关掉，把 JSON 结构写对。

JSON Schema 的三处易错点

工具调用 JSON Schema 里最容易翻车的是参数。一是 required 不写全，模型会把日期和城市名瞎填，我漏写 required 后它连续三次传了空字符串，接口直接 400。二是枚举不给全，城市参数只写 description 不写 enum，它返回杭州余杭区这种带区县的名字，我的接口只认杭州，匹配失败。三是嵌套对象层级太深，两层以上它就开始漏字段，我现在把参数拍平成一层。并行调用也要注意：一次问天气加快递时，第二个调用的参数会丢，解决方法是让模型分两轮调用，别贪快。每次改完 Schema，先拿三个固定问题回归测试，别等上线才发现参数错位。

三个坑

一是流式返回下工具调用参数是分片下发的，按 index 拼接再解析，直接对每片做 JSON 解析必然报错。二是回传工具结果必须用工具角色，混进用户消息里模型会当成新问题重新回答。三是超时要设，我给的十秒偏短，查快递接口偶尔超过十二秒，现在改成二十秒加三次重试。另外 Qwen3-235B 效果最好，但日常测试用 8B 版本更快，调 Schema 阶段没必要烧大模型。工具调用 JSON Schema 的规范各家略有差异，换模型前先对照一遍文档，别把旧 Schema 直接搬过去。

总结

通义千问 Qwen3 函数调用难的不是模型，是参数定义和调试顺序：先关思考模式跑通链路，再补 required 和枚举，最后处理流式和重试。这套顺序反了，很容易误判成模型不会用工具。调通后把 Schema 和回归问题存成文件，下次换模型直接复用，省一半时间。
