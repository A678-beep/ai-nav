表格 转 数据库：结构设计与清洗顺序

实用工具·更新于 2026-11-15·表格 转 数据库, Excel 转 数据库, 表格 清洗, 数据库 表结构 设计, Excel 转 数据库 字段 类型, 表格 导入 数据库 报错

公司用 Excel 管客户和订单，32 张表、3 万行，vlookup 套了四层，刷新一次 40 秒，合并单元格一求和就崩。上个月同事把 20 位订单号粘进数字列，Excel 转成科学计数法，保存后精度丢了 4 位，只能找渠道重新要数据。我花两天把 3 万行搬进 MySQL，整理出 表格 转 数据库 的三步：结构设计、数据清洗、导入验收。

结构：先拆表，再定字段

先做字段清单，每列写名称、类型、长度、必填、示例值，一列一行。宽表拆三张：客户表以客户号为主键，订单表以订单号为主键、客户号做外键，明细表挂在订单号下。类型是重灾区：手机号用 varchar(20)，别用 int，前导 0 和科学计数法都会丢；金额用 decimal(10,2)，float 累加会差出几分钱；日期统一 date 或 datetime，格式 YYYY-MM-DD；状态用 tinyint 配枚举字典，别存「已支付」这种中文串。列名小写加下划线，中文列名在跨工具导出时最容易乱码。索引只给高频条件：手机号、订单号建唯一索引，下单时间建普通索引，每列都建反而拖慢写入。Excel 转 数据库 字段 类型 定错，改起来比重导一遍贵得多。

清洗：五类脏数据先修

合并单元格先取消合并，Ctrl+G 定位空值，输入等号引用上一格再按 Ctrl+Enter 批量填充。首尾空格用 TRIM 清一遍，全角字符转半角。日期最麻烦：45000 这种是 Excel 序列号，文本写的「2026.1.5」也要统一，导入后 0000-00-00 会直接报错。重复按手机号或订单号去重，3 万行里我清出 1400 行重复。长数字——18 位身份证、20 位订单号、银行卡号——粘贴前先把列设成文本，已经变成科学计数法的没法还原，只能重新采集。最后跑校验：手机号匹配 1[3-9] 开头的十一位，金额两位小数，必填列非空，不合格的先人工看。清洗这一步花的时间，通常是结构设计的两倍。

导入：工具、批量与案例

两万行以内用 MySQL Workbench 的 Table Data Import Wizard，它只吃 CSV，表头与字段一一对应，字段含逗号要加引号，文件存 UTF-8 无 BOM。数据量大就用 Python 的 pandas 配 SQLAlchemy，to_sql 设 chunksize=1000、method='multi'，3 万行 45 秒进完。先导入临时表，再用 INSERT INTO 加 SELECT 转正，出错能整体回滚。建库就选 utf8mb4，连接串带 charset=utf8mb4，否则中文乱码、表情符号直接报错。案例：清洗后剩 2.86 万行，原来 vlookup 一次 40 秒，按手机号建唯一索引后查询 0.03 秒，月底报表从手工一小时变成自动跑。表格 转 数据库 的验收就三条：行数对得上、金额合计对得上、抽样十行能倒查。表格 导入 数据库 报错 八成集中在编码、日期和外键顺序，先导客户再导订单，别反过来。

总结

顺序就三步：字段清单加拆表、五类脏数据清洗、临时表加大批量导入。表格 转 数据库 最容易翻车的是长数字，Excel 转成科学计数法保存后不可逆，只能重新采集。Excel 转 数据库 字段 类型 要连同字符集一起定，上线后改表的代价比重跑一遍高。表格 导入 数据库 报错 先查编码和日期，能省掉一半排查时间。
