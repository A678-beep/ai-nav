DeepSeek R1 本地部署 显存要求实录

对话AI·DeepSeek R1, 本地部署, 显存要求, R1 显存对照表, Ollama 部署 R1

我在一台 4060 Ti 16G 加 32G 内存的机器上折腾 DeepSeek R1 本地部署，前后试了 7B、14B、32B 三个规格，结论先说：4bit 量化下，显存要求大致是参数量的 0.6 到 0.7 倍。7B 约 5G，14B 约 10G，32B 约 22G，70B 要 43G 左右，官方 671B 满血版就别想单机了。别急着买卡，先用手头的机器跑一遍再决定。测试方法很土：用 nvidia-smi 看显存占用，用 ollama run --verbose 看每秒 token 数，同一批提示词跑三遍取中位数。

从 Ollama 开始，先跑 14B

Ollama 部署 R1 是最省事的路径：装好客户端，一行命令 ollama run deepseek-r1:14b，默认拉 Q4_K_M 量化，下载约 9G。跑起来先用 ollama ps 看显存占用，14B 在 16G 卡上占 10G 出头，剩下几 G 留给上下文。想省显存就把上下文压到 4K 以内，想跑长文换 Q4_K_S 或直接上 32B。拉模型时可以先用 deepseek-r1:7b 试水，下载 5G，跑顺了再换大的；每个量化版本在 Ollama 里就是一个标签，切换只需改冒号后的后缀。Windows 和 macOS 都有一键安装包，Linux 用一行 curl 脚本，装完先 ollama list 确认模型在列表里。下载前确认磁盘留两倍空间，14B 的权重 9G，加上缓存，40G 的盘会告急。32B 版本 4090 24G 能勉强跑，但上下文给到 8K 就开始掉速，首 token 要等三四秒；70B 用 Q4 要双卡，单卡 24G 只能 CPU 卸载，速度掉到 3 到 5 token 每秒，基本只能当玩具。

数字要按场景看

我的实测：14B 写 800 字产品说明约 40 秒，平均 18 token 每秒；32B 同样任务 90 秒但术语准确率高一些；同一道鸡兔同笼，70B 蒸馏版做对了，7B 版本算错两次，14B 一次对一次错。速度上 7B 在 16G 卡能到 35 token 每秒，14B 18 左右，32B 只有 9，一上长上下文全部腰斩。KV 缓存按上下文线性涨，14B 每 1K 上下文大约多占 100M 显存，32K 就是 3G 多，超出显存就自动卸载到内存，32G 内存跑 32B 长上下文会明显卡顿。在 16G 卡上把 32B 跑起来，本质是拿内存换速度，任务一大就排队等显存，想快只能降规格。上面这组数字就是我的 R1 显存对照表，买卡前先对一眼，比看跑分有用。

三个坑

一是 671B 满血版权重加显存要 700G 以上，普通主机不可能，网上说家用机跑满血 R1 的多是标题党。二是 Ollama 部署 R1 时默认上下文只有 2K 左右，不显式传 num_ctx 时超过的部分会被静默截断，长文总结缺章少节九成是这个问题。三是默认 Q4 量化会轻微掉精度，做合同条款、财务数字这类任务建议 Q5 或 Q6，显存不够就换小规格。另外模型动辄 9G 到 40G，pull 断了不续传，网络不稳就先下 GGUF 再导入；DeepSeek R1 的思考过程会输出一大段推理，token 消耗是普通模型的两三倍，按次计费的接口要先算成本。最后提醒一句，笔记本的 16G 显存和台式机不是一回事，功耗墙一压，速度直接少一半。

总结

DeepSeek R1 本地部署的显存要求可以按 4bit 量化记忆：14B 看 10G、32B 看 22G、70B 看 43G。家用首选 14B，预算够上 32B，别信满血版能塞进消费级显卡。先量显存，再选规格，最后才谈效果。另外 R1 的强项是推理，写创意文案反而不如普通模型听话，别拿它包打天下。买卡前把 R1 显存对照表存进手机，装机时对着看，少走弯路。
