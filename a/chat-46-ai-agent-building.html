AI Agent 搭建：工具、拆解与失败处理

对话AI·更新于 2026-11-15·AI Agent 搭建, Agent 工具 调用, 任务 拆解, 失败 重试, AI Agent 搭建 步骤, Agent 工具 调用 报错

电商售后那套 Agent 是去年接的活：每天 800 单退款和补发咨询，三个人盯到晚上八点。第一版两周上线，自动解决率 41%，还出过一次重复退款，一天 7 单。AI Agent 搭建 不是换个更聪明的模型，是把模糊的活拆成机器能验证的步骤。

边界与工具：一类意图一个 Agent

AI Agent 搭建 步骤 我按四段走：定意图、配工具、写状态机、压失败率。先划边界，一个 Agent 只接一类意图；售后拆成退款、补发、催发货三条路由。工具最多给 7 个，超过之后选择准确率从 92% 掉到 78%，这是 300 条工单量出来的。每个工具描述写 80 到 150 字，必须带不适用场景，比如“补发申请：商品已发出且用户要求重寄，不适用于仅退款”。参数用枚举，别让模型自由填金额和单号。要可视化就用 Dify 或 Coze，一周能搭完；要接内部状态机和幂等逻辑，用 LangGraph 写循环更可控。MCP 能复用内部工具，代价是返回全进上下文，日志接口先做截断。

失败处理：三层分治，别让模型猜

Agent 工具 调用 报错 分三种。参数错最好办：JSON Schema 校验加报错原文回填，最多重试 2 次，temperature 压到 0.1，我这 63% 的参数错第二次就改对。业务失败不重试，换路径：退款接口回“已超售后期”就走补发或转人工，硬重试只会耗死工单。状态不明最危险，超时 60 秒或断网时模型不知道请求成没成，写操作必须带幂等键，先查后写。再补两条：连续 3 次同一工具同一参数就强制中断，总步数上限设 8，超了转人工。改完跑 120 条失败样本回归，重复退款 7 单降到 0，平均步数 9 降到 4.2，自动解决率 41% 到 68%，每单成本约 0.08 元。

上线前先跑评测集，再灰度

评测集 300 条真实工单、5 类意图，只看三个指标：解决率、平均步数、误操作率。第一版没评测直接全量放，第三天就把仅退款执行成退货退款被投诉。之后每步记工具名、参数、返回、token、耗时，投诉时按单号回放整条链路。灰度先放 10% 流量跑一周，人工抽检 20%，只盯两处：金额地址有没有动错、承诺时效有没有说错。权限也收：Agent 只能读订单和物流，退款写操作走审批队列，超过 500 元转人工。还有一条，上下文超过 3 万 token 它开始忘约束，历史消息要压成工具结果摘要。评测集每类意图至少 40 条，比例和线上一致，别拿 100 条简单咨询糊弄自己。

总结

AI Agent 搭建 步骤 落到纸上四行：一类意图一个 Agent、工具不超过 7 个、失败分三层、评测集先跑。Agent 工具 调用 报错 的样本别删，攒起来就是回归集，我攒到 400 条后每改一次提示词都先跑一遍。AI Agent 搭建 省下的不是写代码的时间，是每天三个人盯工单的时间。工具描述和失败样本这两样留好，换人接手也能跑。
