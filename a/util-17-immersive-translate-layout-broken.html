沉浸式翻译 网页 排版 乱：CSS 修复清单

实用工具·更新于 2026-11-15·沉浸式翻译 网页 排版 乱, 沉浸式翻译 自定义 CSS, 双语对照, PDF 翻译, 双语对照 排版 错位, 原文 对照 模式

上个月帮同事看一个行情站，插件一开双语，三列卡片掉成两列，右侧目录被顶到页顶，表格里的数字挤成一竖排。不是插件坏了，是译文把容器撑高了。沉浸式翻译 网页 排版 乱 我按三层处理：先换显示模式，再补 CSS，最后单独调 PDF，前后试过 20 多个站，九成在前两步就能解决。

一、先切模式，别急着改 CSS

双语对照 排版 错位 的根源就一条：译文接在原文段落下面，高度直接翻倍，写死高度或用 flex 的容器立刻裂开。先点扩展图标，在翻译按钮左边的切换按钮切到仅译文，页面高度回原样，问题当场消失，代价是核对原文要再切回来。我的规矩：读长文用双语对照，看后台、卡片列表、表格一律仅译文，PDF 另算。原文 对照 模式 在窄屏上还有毛病，一段 80 字的译文换 6 行，列表项对不齐，窗口拉到 1440 宽以上才勉强够。切完要刷新重翻，没刷新就以为设置无效。

二、五条 CSS 规则，先存成一份

广告位（文章中部）AdSense / 广告联盟代码插入点 · 建议 728×90 / 移动端 320×100

沉浸式翻译 网页 排版 乱 的修法，常驻的 CSS 就五条，写进开发者设置里的用户配置（injectedCss），刷新就生效。一是 .immersive-translate-target-wrapper { display: block !important; }，让插件插进来的双语段落按块级占行；二是 .card、.post、article { height: auto !important; max-height: none !important; overflow: visible !important; }，放开写死的高度；三是 .list、.grid { flex-wrap: wrap !important; align-items: flex-start !important; }，卡片恢复换行；四是 pre、code { white-space: pre !important; overflow-x: auto !important; }，代码块不折行；五是 img、video { flex-shrink: 0 !important; max-width: 100% !important; }，图片不被译文挤扁。只修单个站就写进那条规则的 globalStyles。仍不生效大概率是 Shadow DOM 或 iframe，CSS 进不去，只能退回仅译文。

三、表格排除和 PDF 设置

表格最容易翻车：一格插进译文，列宽全乱。在开发者设置里加一条规则，用 excludeSelectors.add 写成 ["table", "pre", "nav", "header"]，这些区域不翻，正文照常；直接写 excludeSelectors 会覆盖插件默认规则，用 .add 才安全。行情站那次的数字：38 张卡片、每张 120px，双语后撑到 210px，1280 宽的屏幕上三列掉两列，右侧目录被顶走。处理顺序是先切仅译文把列数拉回来，再粘第一、第三条 CSS，最后排除 .data-table，全程 12 分钟，换到下一个博客只改了两个类名。

PDF 又是另一套。免费版只接标准 PDF，扫描件和公式识别走 PDF Pro；纯文本识别对公式和表格本来就不准，公式页直接看原文。面板上三个开关值得动：带图模式影响阅读就关；重叠限制别关，关了上下两段会叠；译文被截断就把文本框拖大；小屏开间距紧凑。新版 BabelDOC 免费每月解析 1000 页、Pro 10000 页，整本 200 页的书分两次翻。先拿 30 页样本试，排版确认没问题再翻整本。

总结

排版乱九成是模式和容器打架：先切仅译文验证，再上五条 CSS，最后给表格和代码加排除规则。双语对照 排版 错位 这类问题，规则存一份，换站只改类名；原文 对照 模式 留给核对，业务页面一律仅译文。PDF 单独调，扫描件走 Pro 或先 OCR，30 页样本过了再翻整本。沉浸式翻译 网页 排版 乱 我一年踩了七八次，最后发现要改的往往不是插件，是站点那几个写死的 height。
