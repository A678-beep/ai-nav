网页 离线 保存：单文件、资源包和阅读器

实用工具·更新于 2026-11-15·网页 离线 保存, 网页保存为单文件, 网页资源打包, 离线阅读器, 网页单文件保存工具, 网页离线资源打包

给一家咨询公司搭竞品资料库，42 个竞品官网、1860 个页面，同事出差路上要查，现场不一定有网。我把 网页 离线 保存 分成三条路：长文用单文件、整站用资源包、长期检索用阅读器，三套一起跑，谁都不替代谁。

一、单文件：一篇一个 HTML

网页保存为单文件 是最省事的做法。Chrome 菜单里「另存为」选「单个文件」，得到 .mhtml，HTML、样式、图片全塞进一个文件，双击能开；麻烦在微信和企业微信打不开，发给客户常被当成病毒。我改用 SingleFile 扩展，存下来是单个 .html，样式跟线上一致，手机浏览器也能看。一篇 60 张图的长文，原始资源 6.1MB，单文件 8.4MB，图片转 base64 会撑大约四成；扩展里关掉隐藏元素、打开压缩 HTML，能压回 6.8MB。网页单文件保存工具 的坑是动态内容：图表靠接口渲染，保存时没加载完，存下来就是空白框，先滚到底再按保存。批量用命令行逐条跑 URL 列表，一页 3 到 5 秒，1860 页跑了两小时。

二、资源包：整站抓下来能翻

竞品官网整站存档，用 网页离线资源打包 更合适。wget 四条参数：-m 镜像目录、-p 下图片和样式、-k 把链接改相对路径、-E 给无扩展名页面补 .html，抓 240 页的站 18 分钟，1.9GB。HTTrack 是图形版，会问代理和限速，公司网络限 300KB/s，不然 42 个站能下一天。两件事必须先做：把懒加载图片滚一遍，让 data-src 换成真实地址；遇到单页应用先用浏览器渲染再存，wget 抓到的只是一层空壳。资源包按「日期加站点名」建目录，双击 index.html 就能翻，适合不会命令行的同事。资源包不存登录态，需要登录的页面抓下来是登录框，这种页面另外走单文件。

三、阅读器：让存档能搜能读

网页 离线 保存 做到第三个月才发现，存下来不等于用得上：单文件和资源包都是文件，找一句话要一个个点开。我在内网起了一个 ArchiveBox，Docker 一条命令，保存时同时出 WARC、单文件 HTML 和截图，1860 个页面 3.2GB，靠它自己的索引能全文搜；另一套 Readeck 更轻，2 核 4G 的机器就能跑，抓正文和标签，手机浏览器能直接读。离线阅读器 选型看两点：能不能全文搜、导出的格式是不是开放标准。同事在 Zotero 里存论文页面快照，跟着文献库走，也够用。避坑一，只存 HTML 不存图片资源，三个月后图片一片 404。避坑二，付费墙和登录页直接存，存下来是墙不是内容。避坑三，单文件超过 15MB 手机浏览器打开会卡，长文拆成几篇。避坑四，mhtml 在 Mac 的 Safari 打不开，跨平台交付统一用 .html。

总结

网页 离线 保存 分三档：长文用单文件，一篇一个 HTML；整站用 wget 或 HTTrack 打资源包，配日期目录；长期资料库上 ArchiveBox 或 Readeck，能搜才算资料。网页单文件保存工具 和 网页离线资源打包 不是二选一，我最后是单文件给业务、资源包给存档、阅读器给检索，三套一起跑才不丢东西。
