代码 注释 翻译 中文：术语表与格式保留

编程助手·更新于 2026-11-15·代码 注释 翻译 中文, 术语表, 格式保留, 增量翻译, 代码 注释 批量 翻译, 英文 注释 转 中文

接手一个 8 万行的 Java 老项目，3400 条注释全是英文，新人看一个类要来回翻。全量翻译我试过直接丢给模型，格式全乱，Javadoc 标签被吃掉一半。后来固定三段：先建术语表，再按语法树只替换注释文本，最后用哈希缓存做增量。代码 注释 翻译 中文 难的不是翻译，是不破坏源文件。

术语表：先定 40 条再动笔

术语表用 JSON 维护，一条英文对一条中文，首现写“中文（英文）”，之后只用中文。我这份 46 条，覆盖 handler 处理器、payload 请求体、idempotent 幂等、backoff 退避、tenant 租户、throttle 限流。规则五条：类名、方法名、配置项、错误码、日志级别不译；Kafka、Redis 这类产品名不译；case 在测试模块译“用例”，在客服模块译“工单”，一词多义按目录分表；中文用全角标点；数字和单位原样保留。术语表和项目一起进仓库，评审时改术语不用动脚本。代码 注释 翻译 中文 里高频小词最容易翻错，术语表外的新词先挂起，人工确认后再补，否则同一个 retry 能翻出三种写法。

格式保留：按语法树定位，不用正则扫行

代码 注释 批量 翻译 我只替换注释节点的文本，注释符号、缩进、空行、换行位置原样保留。// 与 /* */、Python 的 #、Javadoc 的 /** */ 分别处理，@param、@return、@throws 里的参数名不译，Markdown 列表符号和示例块内容不译，issue 号与版本号不动，TODO、FIXME 大写标记保留。多行注释先按行拆开逐行翻，再按原缩进拼回去，块注释行首的星号要保留。行宽按 checkstyle 控在 100 字符，中文变宽后要按显示宽度重排，超宽的行尾注释改成上一行独立注释。避坑：正则匹配双斜杠会误伤字符串里的地址和路径，必须走 tree-sitter 或语言 tokenizer；老项目是 GBK，翻完统一转 UTF-8 并同步改构建脚本，否则日志全是乱码。

增量：只翻改动过的注释

代码 注释 批量 翻译 的增量，靠一个缓存文件 .comment-cache.json，存三样：文件相对路径、注释原文的 sha1、译文。每次先 git diff --name-only 拿改动文件，逐条比对原文哈希，命中直接用旧译文，没命中才发请求。请求按文件攒批，一次 30 条注释、控制在 2k token，temperature 设 0.2，返回后校验条数一致、占位符数量一致、标识符没被翻掉，失败就 checkout 该文件。全量 3400 条跑 41 分钟、12 万 token、账单 0.9 元；第二天改了两个类，增量只翻 37 条，14 秒完事。英文 注释 转 中文 最怕拿行号做缓存键，插几行新逻辑缓存全失效，用原文哈希才稳。

总结

现在这套流程换语言也一样：tree-sitter 定位节点、术语表约束用词、哈希缓存管增量。代码 注释 翻译 中文 做完那 3400 条，编译和单测全过，新人读代码从两天缩到半天；英文 注释 转 中文 的收益不在翻译本身，在于把注释里过期的设计暴露出来，顺手删了 120 条和实现对不上的注释。避坑最后一条：翻完一定跑一次构建，模型偶尔把全角括号带进代码行。
