ChatGPT 连接超时 5 步排查记录

对话AI·更新于 2026-11-15·ChatGPT 连接超时, ChatGPT 打不开, 网络排查, ChatGPT 打不开怎么排查, ChatGPT 一直转圈

周一早上 9 点 20 分，离站会还有十分钟，ChatGPT 页面白屏了 40 秒，最后浏览器甩出一行 ERR_CONNECTION_TIMED_OUT。同一个代理节点，同事的电脑能正常对话。我先花五分钟看服务状态，再按报错码分层排查，前后 50 分钟才定位到家里宽带的 IPv6。那次 ChatGPT 连接超时的排查顺序我记了下来，五个步骤，每一步都能复现。

第一步：先看报错码，别急着换节点

打开浏览器 F12 的 Network 面板，刷新页面，看第一条 chatgpt.com 文档请求的状态。如果它长时间 pending，最后标红 net::ERR_CONNECTION_TIMED_OUT，说明本机到目标服务器连 TCP 都没建起来；如果返回 1020 或 524，那是 Cloudflare 风控或回源超时，方向完全不同。接着在 PowerShell 里跑 Test-NetConnection chatgpt.com -Port 443，TcpTestSucceeded 显示 False 就是 TCP 不通；再想确认握手，用 openssl s_client -connect chatgpt.com:443 -servername chatgpt.com，卡在 CONNECTED 之后没有证书链，就是 TLS 被中间设备拦。最后用手机热点复测一次，热点能开，问题就在本地网络或代理。这一步能砍掉一半无效操作，也是我处理 ChatGPT 连接超时最先做的事。

第二步：代理、DNS、IPv6 逐个确认

先确认流量真的进了代理：打开任意查 IP 的页面看出口地址，v2rayN 默认本地 SOCKS 是 10808、HTTP 是 10809，端口被改过就按实际填。系统代理模式只接管遵守系统代理的软件，浏览器插件会绕过，必要时切 TUN 模式。分流规则要同时覆盖 chatgpt.com、auth.openai.com、oaistatic.com、oaiusercontent.com 四个域名，漏掉登录域名就会出现首页能开、ChatGPT 一直转圈的情况。DNS 交给代理做，本地运营商解析经常把地址污染成不可达 IP，用 nslookup chatgpt.com 1.1.1.1 对比一下就能看出来。IPv6 是最隐蔽的：解析返回 AAAA 地址、线路却不通，浏览器会先等二十多秒再回退。我在网卡属性里取消勾选 Internet 协议版本 6(TCP/IPv6)，首字节时间从 21 秒掉到 1.3 秒。

第三步：复测与两个真实坑

上个月公司内网也出过一次：网关做 TLS 解密，网页报 ERR_CONNECTION_RESET，换成热点正常，最后是 IT 放行了相关域名。另一个坑是刷新，Cloudflare 那边我连续刷新十几次后直接返回 Error 1020 Access denied，换节点等半小时才恢复，所以同一页面刷新不要超过五次。页面能开、消息发不出去是另一种情况，属于长连接被中途断开，这时候重点看节点丢包，别去改浏览器缓存。想搞清楚 ChatGPT 打不开怎么排查，记住顺序就行：状态页、报错码、命令行分层、代理与 DNS、热点复测。最后两个提醒：系统时间误差超过五分钟会让 TLS 校验失败，打开自动设置时间并手动同步一次；别用 hosts 硬写 IP，CDN 调度一变，表现就是能打开首页、每条消息都超时。

总结

跑完这一轮，我的结论是：ChatGPT 连接超时九成出在本地链路，顺序千万别反。先看 status.openai.com 确认服务端没事，再用 F12 和命令行把 DNS、TCP、TLS 三层分开，最后才动代理设置。ChatGPT 一直转圈时尤其要克制刷新，等三十秒比连点十次有用。按这套流程走，后来再遇到同样的 ChatGPT 连接超时，我平均十分钟内能定位；ChatGPT 打不开怎么排查这个问题，也基本能当场给同事一个答案。
