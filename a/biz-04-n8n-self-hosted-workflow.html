n8n 自建 工作流：Docker 三步部署

商业效率·更新于 2026-11-15·n8n, 自建工作流, 定时任务, n8n Docker 部署, n8n 定时触发

内容组每周要盯 20 个竞品博客和公众号，人工摘录进飞书表格，一个人一周 5 小时。我用 Docker 在 2 核 2G 的 VPS 上自建 n8n，配一条定时工作流：抓 RSS、去重、AI 摘要、写进多维表格、发群通知。服务器 $6/月，对比 n8n Cloud Starter 的 $24/月，省下的钱不多，但数据留在自己机器上。n8n 自建工作流真正的成本是维护，不是订阅费。

一、部署就三步

第一步，跑 docker run -d --name n8n -p 5678:5678 -v n8n_data:/home/node/.n8n docker.n8n.io/n8nio/n8n，把数据卷挂出来，升级不丢凭证。第二步，用 Caddy 配 443 端口的反向代理和自动证书，webhook 必须走公网域名，否则飞书回调收不到。第三步，进 Settings 把时区改成 Asia/Shanghai，再建第一个定时触发节点。

2 核 2G 跑 20 条工作流，内存占用大约 700MB，超过 50 条建议上 4G，否则触发高峰会 OOM 重启。n8n Docker 部署最省事的其实是升级：拉新镜像、删旧容器、保留数据卷，三条命令换完。另外，n8n 官方节点里没有飞书多维表格，得在 Settings 的社区节点里填包名装插件，装完重启容器才生效。n8n Docker 部署还有一个细节：容器重启策略设 always，服务器重启后工作流自动恢复，不然周一早上你以为是定时任务没跑，其实是容器没起来。数据卷每天 rsync 到对象存储，$1/月就能保住全部历史执行记录。

二、三个我踩过的坑

避坑一，加密密钥。n8n 把凭据加密存在数据卷里，N8N_ENCRYPTION_KEY 不写死，重装容器后飞书、OpenAI 的所有凭据全部解不开，只能重新授权一遍。避坑二，重复执行。定时触发每 30 分钟跑一次，抓 RSS 时同一篇文章会重复入库，用发布时间做去重，别只按标题。避坑三，版本升级。升级前把工作流导出成 JSON 存一份，社区版大版本升级有节点参数改名的情况，我从 0.9 升到 1.x 时飞书节点一个字段名变了，整条链路静默失败，日志里只报 undefined。

还有一个小坑：飞书多维表格的字段名带空格时，节点里的字段映射要手写点号路径，别用自动匹配，自动匹配会把空格吃掉。

三、省钱账要算清楚

n8n 定时触发每 30 分钟一次，一天 48 次，20 个源大约 300 条/天，一个月约 9000 次执行。n8n Cloud Starter 只含 2500 次执行，超量要加钱；自建只看 VPS 和模型费。摘要用便宜的小模型，一条成本约 $0.0004，一个月 3.6 美元，合计 $10 出头。定时任务是 n8n 最稳的用法，8:00 到 22:00 每 30 分钟跑一次，目标站超时就重试三次，第一个月跑了 8900 次，失败 12 次，全都自动重试成功。VPS 选带快照的，升级翻车直接回滚，比从头装快得多。n8n 自建工作流的好处是没有执行次数上限，坏处是服务器得自己盯。

总结

自建 n8n 的账要算维护：一个月花 1 小时看日志、备份数据卷，换来数据不出内网。三步部署、写死加密密钥、n8n 定时触发配上去重，这条 n8n 自建工作流就能稳定跑一年。一年省下的 120 小时不是工具给的，是把抓取、摘要、入库、通知拆成可复跑的节点之后省出来的。
