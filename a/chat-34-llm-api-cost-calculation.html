大模型 API 成本核算：按业务量算清每月账单

对话AI·更新于 2026-11-15·大模型 API 成本, API 成本核算, token 预估, 阶梯计价, 大模型 API 成本怎么算, API 成本怎么估算

「老板问，这个 AI 客服一个月烧多少钱？」我第一版按每次一分五拍了个 90 元/月的数，月底账单 168 元，差 87%。不是单价看错，是业务量估错：轮次会累加、长会话会落进更贵的档、重试也在计费。后来我把 大模型 API 成本 拆成三步算——数请求量、量真实 token、按长度套价，误差压到 6%。

第一步：请求量按轮次累加

别拿「用户数×每天次数」当业务量。日活 300 的客服机器人，人均 4 次会话、每次 6 轮，一天不是 1200 次请求，而是 7200 次。更麻烦的是 token：第 1 轮只发 800 token，第 6 轮要把前 5 轮历史带上，单次输入接近 4800 token。按增量乘以轮次估，一个会话的输入约 1.7 万 token，不是 800 乘 6 的 4800。再补两类常漏的量：接口超时重发、函数调用多走一轮，都单独计费，我的记录里重试占请求量 7%。

token 也别用字数乘固定系数。我把线上 200 条真实请求导出来，看接口返回的 usage 字段，中文客服语料平均 1 字 0.8 个 token，换另一个分词器的模型是 1.15 个，差四成。API 成本怎么估算，第一步就是把这四个数写纸上：日均请求、单次输入、单次输出、重试率。

第二步：阶梯价按单次请求落档

多数平台按单次请求的输入长度分档，常见 0-32K、32K-128K、128K 以上三档，后两档输入单价约是第一档的 3 倍和 6 倍。反直觉的坑在这：阶梯按一次请求判，不按月总量打折。我把一份 60K 的合同拆成两次 30K 的请求，两段都落在最便宜那档，同样的 token 数账单少四成；把两段合并发给模型，全量按 3 倍价算。

缓存是第二根杠杆。主流接口的缓存读价是原输入价的 0.1 到 0.5 倍，写入加价约 1.25 倍，只对固定前缀划算。system 提示、输出格式、工具定义放最前面，时间戳和订单号往后挪。客服机器人固定 system 2.4K token，命中率从 0 提到 82% 后，每千次请求的输入费从 4.8 元降到 1.3 元。

第三步：拿一个月的账本对一遍

电商客服摘要的实测：日均 200 次，每次输入 8000 token（其中 2.4K 走缓存），输出 600 token。按未命中 2 元/百万、命中 0.2 元、输出 8 元算，一天 3.3 元、月 99 元。账单实际 168 元，多出的 69 元全在长会话：9% 的请求输入超 32K，落进 3 倍档，吃掉了四成费用。我按长度重新分桶，再乘 1.07 的重试系数，算出 179 元，误差 6%。

两个避坑。一是限流重试要算账：并发超了接口返回 429，脚本自动重试三次，账单多 15%。二是报价别用裸成本：我按 179 元测算，对外报 230 元，留 30% 余量，再注明超出按 usage 结算。大模型 API 成本怎么算，对一次账单比估十次都准。

总结

现在固定成一张表：日均请求数（含重试）、单次输入输出 token（取线上样本中位数）、输入按长度分桶乘阶梯价、命中部分乘缓存价，最后加 30% 余量。每月对一次 usage 和账单，误差超过 20% 先查长会话占比和缓存前缀。大模型 API 成本怎么算，答案不是套单价，而是把自己业务量拆到「次」和「轮」。API 成本怎么估算 做一遍实测，就不会再想拍脑袋了。
