Cursor 中文乱码：3 步改回 UTF-8

编程助手·更新于 2026-11-15·Cursor 中文乱码, 文件编码, UTF-8, Cursor 中文乱码怎么解决, Cursor 终端乱码

接手一个 2019 年的 Vue 项目，用 Cursor 打开 .js 文件，注释全是锟斤拷锟斤拷，字符串里的中文变成一串问号。更麻烦的是让 Agent 改一个函数，它读进去再写回来，原本只是显示乱码的几行变成了真正的乱码字节。Cursor 中文乱码不是编辑器坏了，是文件编码、终端编码、Agent 编码三层里至少一层对不上。

先分清三种乱码

第一种是文件本身用 GBK 或 GB18030 保存，Cursor 按 UTF-8 解码，整篇中文都乱，右下角状态栏还写着 UTF-8。第二种是终端输出乱，PowerShell 用系统代码页 936 输出中文，Cursor 终端按 UTF-8 读，git log 里的作者名就花了。第三种是 Agent 执行命令后返回的乱码，Cursor 官方论坛承认过这是中文 Windows 上的已知问题：agent shell 按 UTF-8 解码命令输出，而系统代码页是 936。判断方法很简单，用 Format-Hex 看文件开头有没有 EF BB BF 的 BOM，再换 VS Code 打开同一个文件对比，就能确定是文件问题还是显示问题。锟斤拷是 UTF-8 的替换字符被按 GBK 解码的结果，烫烫烫来自没初始化的内存，看到这两个词基本不用怀疑编码。

文件和终端的改法

广告位（文章中部）AdSense / 广告联盟代码插入点 · 建议 728×90 / 移动端 320×100

文件乱的修法：点右下角编码，选 Reopen with Encoding，挑 GB18030，它是 GBK 的超集，生僻字也能正确显示；确认中文正常后，再点 Save with Encoding 存成 UTF-8，别选带 BOM 的版本。Cursor 终端乱码的修法：在 PowerShell 的 $PROFILE 里加三行，[Console]::OutputEncoding = [System.Text.Encoding]::UTF8、$OutputEncoding = [System.Text.Encoding]::UTF8，再执行 chcp 65001；把 Cursor 的默认终端换成 PowerShell 7，它默认按 UTF-8 读写；Git 里跑一次 git config --global core.quotepath false，中文文件名就不再转义。想一劳永逸统一设置，在 Cursor 的 settings.json 里写 files.encoding 为 utf8、files.autoGuessEncoding 为 true，项目里放 .vscode/settings.json 和 .editorconfig，charset 写 utf-8。Cursor 不读 VS Code 的配置，它自己的路径是 %APPDATA%\Cursor\User\settings.json，两边各配一次才稳。

两个坑和一次迁移

迁移那 7 个 GBK 文件时我踩了两个坑。第一个是顺序：看到乱码直接 Save with Encoding，等于把错误解码后的字重新编码写回，原来的字彻底没了，正确顺序永远是先 Reopen 确认显示正常，再 Save。第二个是 BOM：为了兼容老脚本我一开始存了 UTF-8 with BOM，结果 Node 读取配置多出三个字节，构建报 JSON 解析错误，团队最后统一无 BOM。另外 autoGuessEncoding 对一 KB 以内的短文件会猜错，中文文件被当成 Shift-JIS 打开也是乱码，所以打开后先看状态栏编码再动手。那个老项目一共 7 个 GBK 文件、3000 多行，我按先 Reopen 再 Save 的顺序 40 分钟处理完，之后 Agent 改文件没有再把字写坏。这类 Cursor 中文乱码怎么解决，关键就是先分清文件层还是终端层；另外 Cursor 终端乱码别去改源码，终端的问题在终端解决，文件的问题在文件层解决，混在一起改只会越改越乱。

总结

现在我的固定动作是：新项目先看 .editorconfig 和文件编码，老文件用 Reopen with Encoding 确认再另存 UTF-8，终端配上 chcp 65001，Agent 改文件前先 git commit。这样处理后，同一个项目里 Cursor 中文乱码再没出现过。真遇到 Cursor 中文乱码怎么解决，先问自己乱的是文件、终端还是 Agent 返回值，这三层对应的修法完全不同，先分类能省一半时间。
