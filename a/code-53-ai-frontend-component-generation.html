AI 前端 组件 生成：props 契约和单测

编程助手·更新于 2026-11-16·AI 前端 组件 生成, 组件 props 设计, 受控 组件, 组件 单测, AI 生成 组件 怎么 验收, 组件 props 命名 规范

上个月给一个 6 人前端组补组件库，缺一个带搜索、多选、远程加载的 Select。手写排期 1.5 天，我让 AI 先生成一版，8 分钟出了 320 行，贴进项目就发现 12 个 props 里 4 个命名和现有组件冲突、键盘 Tab 走不出下拉、禁用态还能点。改到能提测又花 3 小时，比手写省一半。AI 前端 组件 生成 快在骨架，慢在 API 和边界，这两样它默认不管。

先写 props 契约，再让 AI 动手

一页纸四列：props 名、类型、默认值、是否必填。每个 prop 写一句用途，默认值标清 undefined 和 null，类型里才会保留可选标记。组件 props 命名 规范 先跟项目对齐：现有组件用 value/onChange，就别让它造 selected/onSelect；受控和非受控二选一，别混着来。受控组件的 value 和 defaultValue 同时出现，React 会报警告。变体用联合类型收口，size 只给 sm、md、lg 三档，variant 只给 default、danger 两种，别让它生成 9 个布尔开关（isSmall、isLarge 这类）。生成顺序固定：先 types.ts，再组件，再 stories，最后单测；一次只生成一个组件，一轮塞 5 个，第 3 个开始互相抄错类型。避坑一：AI 爱在组件里直接 fetch 数据，组件库必须纯展示，数据只从 props 进。

无障碍和状态，是 AI 的固定短板

广告位（文章中部）AdSense / 广告联盟代码插入点 · 建议 728×90 / 移动端 320×100

我拿 20 个生成组件过 axe，14 个有 aria 问题：div 当按钮、缺 aria-expanded、焦点不回到触发器。Select 的键盘要覆盖 Tab、上下键、Enter、Esc 四个键，AI 第一版只做了点击。焦点管理我固定测三件事：打开后焦点进第一个选项、Esc 关闭后回触发器、Tab 不跑出弹层。状态补 5 个：loading、空结果、禁用、错误、超长文本；长文本最容易漏，选项 30 个字就把下拉撑破。用 Radix Primitives 或 Ant Design 的底层当底座，让 AI 只写业务层，aria 和 focus trap 交给库；第二版这么改，axe 报错从 14 个降到 2 个。避坑二：别让它用内联 style 写死 px，组件库要支持主题，颜色只能取 CSS 变量或 token。AI 前端 组件 生成 的返工，八成出在这两类问题上。

单测写 12 条，别追覆盖率

12 条分四组：正常选中、多选上限、禁用和加载、键盘与焦点。断言看行为不看实现：点选项后 onChange 收到的值、下拉是否关闭、焦点是否回到按钮。工具用 Vitest 加 Testing Library，跑一次 3 秒；再补 3 个 Storybook 故事，默认、多选、空态，给设计走查用。覆盖率只做参考，我卡行覆盖 80%、分支 70%，为凑数写实现细节的断言，重构全得改。验收四条：tsc --noEmit 零报错、eslint 零 warning、axe 零 critical、单测 12 条全绿。第一版 320 行改到 240 行，props 从 12 个收到 8 个，12 条单测里 5 条一开始是红的。12 条里至少 3 条测失败路径。AI 生成 组件 怎么 验收，就看这四条，别只看页面能不能点。

总结

顺序是：props 契约一页纸、先 types 后组件、无障碍交给底座、12 条单测收尾。一个 Select 从 1.5 天压到 3 小时，返工两轮，上线后组件相关 bug 是 0。这套规则每生成一次就补进文档。AI 前端 组件 生成 省的是搭骨架，组件 props 设计 和边界状态还得人定；AI 生成 组件 怎么 验收，四条硬指标比覆盖率有用。组件 props 命名 规范 写进团队文档，下次生成前直接贴给模型。
