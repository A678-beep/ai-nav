接口 Mock 工具 选型：3 款实测对比

编程助手·更新于 2026-11-15·接口 Mock 工具, 接口 Mock 服务, Apifox, MSW, WireMock, Mock 数据 生成, 前后端 联调 Mock

上个月接了个 47 个接口的活动页，后端排期在第 9 天，前端干等就废了。我们拉了三个 接口 Mock 工具 做实测：Apifox 管文档和团队环境、MSW 管前端本地拦截、WireMock 管故障注入和回放，各管一段。三天把 Mock 层搭起来，前端第 1 天就开工，联调 4 天收尾，比原计划少 5 天。

选型：三款工具各管一段

Apifox 适合有 OpenAPI 文件的团队，导入接口定义后自动生成接口 Mock 服务，响应延迟按接口设，6 个人共用一套环境，改字段先改文档再同步 Mock。MSW 是前端本地拦截，Service Worker 层拦 fetch，handlers 和真实请求写法一致，同一份 handlers 能在浏览器和 Vitest 里复用，切到真实接口只改一个环境变量。WireMock 3.x 用 Docker 起一行 docker run -p 8080:8080 wiremock/wiremock，擅长故障注入和录制回放，加 --proxy-all 把真实响应录下来，改两行就能回放。JSON Server 只适合一两个人的原型，db.json 一改全队互相覆盖，47 个接口的项目不建议。接口 Mock 工具 别求一款全覆盖，按谁要用、用来干什么分最省事。

约定：Mock 数据先对齐契约

接口 Mock 工具 只是前半段，字段对不上照样翻车。我们先把约定写进 docs/mock-convention.md：统一响应体 code、message、data，分页结构放 data.list 加 data.total，时间一律 ISO 8601 带时区，金额用分存整数，错误码集中在 1000 到 1999 段。然后从 OpenAPI 文件生成 Mock，字段类型必须和 schema 一致，boolean 不能图省事写成字符串 "true"，否则前端判断永远为真。Mock 数据 生成 分三档：正常值占 70%，边界值占 20%，含空数组、null、2000 字长文本、emoji，异常值占 10%，含 500、超时、字段缺失。随机数据要固定 seed，不然每次跑结果都在变，断言没法写。这里有个小技巧：用脚本按比例灌数据，比在界面上点随机可靠。

联调：延迟和故障要主动注入

联调阶段最怕 Mock 太完美，页面全绿，一接真后端就白屏。我们的做法是：本地 dev 用 MSW，接口延迟统一加 300ms；联调环境用 WireMock，按场景注入 500、504 和 5 秒超时，订单状态用 Scenario 做流转，未支付到已支付到已发货各写一条映射。每条列表都要求有空状态和加载失败的兜底，验收时把 Mock 调到返回空数组和 500 各跑一遍。案例：47 个接口里上线前抓出 12 处类型不一致，Mock 返回字符串而真实接口返回数字，还有 3 处字段改名后 OpenAPI 和 Mock 没同步，前端白屏。两个避坑：Mock 域名别混进生产包，环境变量没切会打过去；Mock 里的订单号别写死同一个，多端同时调试会串数据。前后端 联调 Mock 这份契约，最好由后端在合并前更新一次 OpenAPI。

总结

这套组合跑了两个项目：Apifox 管文档和团队环境，MSW 管前端本地和单测，WireMock 管故障注入和回放。接口 Mock 工具 选型看三件事：团队能不能共用一套环境、数据能不能按 schema 自动生成、故障能不能主动注入。Mock 数据 生成 和前后端 联调 Mock 的约定写进仓库，比买贵的工具更有用。
