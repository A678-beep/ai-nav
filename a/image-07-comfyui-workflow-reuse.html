ComfyUI 工作流 复用：3 个子图

图像生成·ComfyUI 工作流 复用, 子图, API 格式, ComfyUI 工作流怎么复用, ComfyUI 工作流导出后打不开

组里 5 个人各有一套 ComfyUI 流程，参数散在十几个节点里，换项目就得重连一遍，谁请假别人接不了手。

上个月我把常用链路拆成 3 个子图做成模板，改一次全线生效，一周省下 4 小时重复劳动。要把ComfyUI 工作流怎么复用做扎实，靠的不是记性好，是结构。

拆子图的步骤

  1. 选中采样相关节点，右键 Convert to Subgraph，命名"采样核心"，把步数、CFG、采样器暴露成输入。
  2. 参考图、蒙版、提示词各做一组输入接口，用红黄蓝三色标注。
  3. 用 Save (API Format) 导出 JSON，存进团队共享目录，文件名带版本号 v2.3。
  4. 换模型时只改子图里的 loader，外层链路不动。

子图拆完先自己跑 10 张确认结果和原链路一致，再把 JSON 发给同事。导出时选API 格式，JSON 里别留本地图片的绝对路径，这套ComfyUI 工作流 复用才算完成一半。

拆子图时不要把模型加载器也封进去，否则换模型还得进子图改。我把 loader 放在外层，子图只留采样和 latent 两个环节，换模型只动一个节点，ComfyUI 工作流 复用才真正省时间。

API 格式导出后建议再用脚本跑一遍，确认 JSON 里的字段名没被节点更新改掉。上周有个工作流在同事机器上出全黑图，查下来是 VAE 节点版本不同，字段名被改过了。

复用的三种场景

同一套出图流程换 3 个模型（SDXL、SD3.5、Flux），只改 loader 和采样器；给同事发工作流先确认对方节点版本；批量跑 200 张，用组节点加旁路开关切参数。子图拆得越细，复用越灵活。

ComfyUI 工作流怎么复用的答案不是保存成模板就完了，而是把会变的部分全部暴露成接口，固定部分封进子图。我通常把 20 个节点压到 3 个子图、18 个可见接口，改图时间从 20 分钟降到 5 分钟。

打不开的坑

ComfyUI 工作流导出后打不开是最常见的报错，导入后一片红框、提示缺节点：对方没装 ComfyUI-Manager 或版本落后两个大版本。导出时附一份节点清单截图，让对方先 Install Missing Custom Nodes 再重启。

还有一种ComfyUI 工作流导出后打不开的情况是模型路径写成绝对路径，换电脑全失效，统一改到 extra_model_paths.yaml。第三个坑是子图里的 seed 被固定，批量出 20 张一模一样，导出前记得改成 randomize。

收益我也算过：以前每接一个项目重搭 40 分钟，现在打开模板 5 分钟，一个月 8 个项目就是 4 个多小时。还有个小坑，子图命名带中文时有些版本导出会乱码，统一改成英文加下划线。

团队协作时把工作流和节点版本一起写进 README，新同事按图索骥装一遍就能跑，省得每次在群里问对方装的哪个版本。

总结

拆子图、暴露参数、存API 格式 JSON、附节点清单，四步做完这套ComfyUI 工作流 复用才算稳定。模板每月更新一次版本号，别让旧节点拖垮新流程。
