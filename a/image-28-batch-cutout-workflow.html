批量 抠图 工作流：1200 张图的自动化

图像生成·更新于 2026-11-15·批量 抠图 工作流, 抠图 API, 目录结构, 透明 PNG, 抠图 API 批量 调用, 商品图 批量 去背景

服装电商客户一次给来 1200 张平铺图，全要透明底 PNG。商品图 批量 去背景 过去是三个人在 Photoshop 里点“选择并遮住”，一天 300 张，边缘还不齐。我把它拆成一条能重复跑的批量 抠图 工作流：原图进目录、脚本出图、拿不准的丢复检。第一次全量跑完 41 分钟，失败 14 张，人工只花 8 分钟。

目录结构：先定命名再谈自动化

目录固定五层，别让脚本满硬盘找图：

batch/
  input/    A1023-1.jpg 原图，按 SKU 命名
  output/   透明 PNG，长边 2000px
  review/   拿不准，等人工
  failed/   重试 3 次仍失败
  run.log
广告位（文章中部）AdSense / 广告联盟代码插入点 · 建议 728×90 / 移动端 320×100

三条规则：input 只读不覆盖；文件名只改扩展名，PNG 与 JPG 同名；路径带中文和空格时用 pathlib 拼绝对路径。脚本启动先自检：五个目录在不在、磁盘还剩多少、output 里有没有同名残图，缺一个就退出。避坑：别按日期建子目录，回收旧图时对不上号；出现 -1、-2 后缀先查是不是重复上传。商品图 批量 去背景 的第一步是把命名理顺，命名乱了复检没法对账。

跑法：本地打底，API 补刀

批量 抠图 工作流 我先跑本地：rembg i input/A1023-1.jpg output/A1023-1.png -m birefnet-general -a -af 240 -ab 10 -ae 10。alpha matting 只在发丝、雪纺、半透明包装上开，-af 240、-ab 10、-ae 10 是常用档位，开太狠白衬衫边缘会被咬掉一圈。4060 8G 上 2000px 单张 1.2 秒，1020 张约 20 分钟。剩下 180 张实景图走阿里云商品分割 API，0.002 元/次、1 万次以内、QPS 5，并发 4，遇 429 按 1、2、4 秒退避，三次失败进 failed。别一上来就全量，先抽 20 张跑样本，看边缘和白底再放队列。模型权重提前备好，u2net 176MB、birefnet 约 900MB，内网机器先拷到 .u2net 目录；抠图 API 批量 调用 的关键不是并发多高，而是失败单独收口。

案例：41 分钟出图，复检 8 分钟

这 1200 张里 1134 张直接过，review 里 52 张是半透明雪纺和金属反光，本地 44 张、API 8 张；failed 14 张是长边超 4096 或纯白背景没主体。复检只看三处：边缘 2 像素内有没有灰边、白底是不是 255 纯白、主体重心是否一致，修 52 张用选择并遮住，每张 9 秒。交付两套：透明 PNG 存档，1500×1500 白底 JPG 上架。第一版我图省事直接输出 JPG，透明区被填成黑色，客户后台全退回。抠图 API 批量 调用 加本地这套跑顺后，同样 1200 张从 3 人 1.5 天压到 1 小时，返工率 8% 降到 1.2%。run.log 记每张图的耗时和模型版本，复检时按 SKU 反查，出问题能定位到具体哪一版。避坑：2000px 透明 PNG 单张 2 到 6MB，别直接传后台，压成带 alpha 的 WebP 能小 60%。

总结

能复用的不是脚本，是三个判断：原图质量决定上限，白底、反光、半透明必须进 review；失败单独收口，重试三次就放行会污染整批；命名和目录一次定死，换模型换 API 都不用改调用方。批量 抠图 工作流 的成本大头在复检，不在抠图本身，把 52 张拿不准的挑出来修，比追 100% 自动化现实。换模型前先拿那 52 张硬骨头做回归，指标不涨就不换。第三方 API 只当兜底，主链路放本地，账单和速度都可控。
