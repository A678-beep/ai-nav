文件 对比 工具：文本、二进制与目录怎么选

实用工具·更新于 2026-11-15·文件 对比 工具, 二进制 文件 对比, 文件夹 对比 工具, 目录差异, 文件夹 对比 工具, 二进制 文件 对比

客户退回来一个素材包，说新版比旧版少了 5 个文件。我手上只有两个 23GB 的文件夹，没有任何清单。用 Beyond Compare 跑目录对比，6 分 40 秒扫完 1.9 万个文件，报出 312 处差异，其中 187 处只是修改时间不同、内容一模一样。文件 对比 工具 用错层级，要么漏掉真差异，要么被噪音淹死；动手前先想清楚比的是文本、二进制还是目录。

一、文本：规则先于速度

纯文本最好比，也最容易误报。Beyond Compare 5、WinMerge 2.16 都能递归比目录、按规则忽略空白和大小写；VS Code 里右键「选择以进行比较」再选另一份，改配置够用；命令行用 diff -u -r 目录，加 -w 忽略空白、--strip-trailing-cr 忽略行尾。三个坑：GBK 存的中文文件按 UTF-8 打开会整篇飘红，先转码；CRLF 和 LF 混用，diff 会把每行都标成不同；全角逗号换半角，肉眼看不出来，diff 直接报 200 行差异。文件 对比 工具 在文本层拼的不是速度，是规则设得对不对；规则设好存成模板，团队共用。

二、二进制：先比哈希，再定位字节

安装包、固件、图片别做逐行比较，第一步比哈希。Get-FileHash 或 certutil -hashfile xxx SHA256，哈希一样就是完全相同，1.9 万个文件 40 秒出结果；厂商随安装包发的 SHA256SUMS 校验文件，就是同一套用法；哈希不同再上 fc /b a.exe b.exe（Windows）或 cmp -l（Linux/macOS），直接告诉你从第几个字节开始不同。注意 docx、xlsx、APK 本质是 zip，重打包一次二进制必然不同，得解压比里面的 XML，或者用 diffoscope，它会写明差异来自签名时间戳还是压缩算法。二进制 文件 对比 的结论只有两种：内容变了，或者只是元数据变了。

三、目录对比与真实案例

目录对比先定三件事：比内容还是比时间、多出来的文件删不删、软链接跟不跟。Linux 用 rsync -ain --checksum 干跑，不动任何文件就列出差异；Windows 用 robocopy /L /MIR 预览覆盖和删除清单。案例那批 23GB 素材，加上 --checksum 后差异从 312 处降到 125 处：187 处是旧移动硬盘 FAT32 格式、时间戳精度只有 2 秒造成的假差异；125 处里 118 个是缩略图被重新生成，7 个是真丢了。7 个里 5 个没扩展名、被上传工具吞了，2 个是文件名里的全角括号变成了问号。文件夹 对比 工具 一定要能导出清单，白纸黑字发给对方，比口头说少 5 个文件有用。避坑三条：OneDrive 按需文件是占位符，直接扫会把云端文件全拉一遍；对比前先暂停同步，不然边同步边比，结果一直在变；路径超过 260 字符时，个别老版本会静默跳过，换支持长路径的版本再扫。

总结

文件 对比 工具 分三层用：文本比规则，二进制比哈希和偏移，目录比清单和排除项。日常文本和目录用 Beyond Compare 或 WinMerge，要可复现就用 diff 和 rsync，二进制深挖交给 diffoscope。二进制 文件 对比 先看格式，文件夹 对比 工具 先停同步，这两个动作能省掉一半误报。
