代码 迁移 语言：Java 转 Go 四步法

编程助手·更新于 2026-11-15·代码 迁移 语言, 语义 差异, 黄金 测试, 灰度 上线, 跨语言 代码 迁移, 代码 迁移 测试 方案

去年把一个 8600 行的 Java 订单服务转成 Go，一共 10 个模块。第一版我直接让 AI 逐文件翻译，编译能过，上线当天就出事：金额按 long 存分，Go 那边有人随手改成 float64，对账差 0.03 元；一个 UTF-16 字符长度判断改成 len(bytes)，中文地址截断成乱码。代码 迁移 语言 难的不是语法，是两套语言对空值、长度、时间、金额的默认假设不同。后来我把流程改成四步，分 7 批迁完，灰度两周，返工压到 3 处。

先跑黄金测试，把行为冻下来

动代码前先给老的 Java 服务拍快照。我从线上日志脱敏导出 800 条真实请求，覆盖 36 个接口，连请求带响应存成 JSON，再用 Go 写一个对照测试：同一批请求分别打老 Java 服务和迁移中的 Go 服务，比较响应字段、状态码、耗时量级。第一批只迁 3 个纯计算函数，800 条全过才往下走。这比普通单测省事，不比内部实现，只比对外行为，老代码的怪习惯也能一起继承，比如金额四舍五入用截断、错误码 2001 的文案带句号。避坑：快照里的时间戳和自增 ID 要先归一化，否则每次对比都 diff 一片红。

分批迁：一张语义差异对照表

迁移按依赖从里往外，7 批、每批 3 到 5 个文件、diff 控制在 400 行内，当天能回滚。每批开工前先填语义差异表，我列了 8 条必查：空值、金额、字符长度、时间、除零、整数溢出、集合排序稳定性、JSON 字段大小写。跨语言 代码 迁移 里最常翻车的是静默差异：Go 的 nil map 写入会 panic，Java 的 HashMap 不会；Go 的 int 在 64 位机器上是 64 位，Java int 固定 32 位，同样的位运算结果会变；Java 的 UTF-16 字符数按 char 算，Go 的 len 按字节算，中文一个顶三个。表填完再让 AI 按表翻译，返工少一半。

AI 干什么、人守什么

AI 适合干三段活：逐函数翻译、补 Go 的 error 返回、写对照测试的胶水代码。我给的提示词固定三句：只改指定文件、保持函数签名和错误码不变、拿不准的语义停下写 TODO 别猜。人守四条线：金额、时间、权限、日志埋点，这四处 AI 十有八九会顺手简化。每批完成跑三重校验：800 条对照测试、20 条边界用例、随机 200 条 fuzz 请求对拍。代码 迁移 测试 方案 里最省事的其实是第四批之后，Go 服务已经能承接三个接口，直接切 5% 灰度流量，真流量比测试用例更会挑毛病。代码 迁移 语言 的顺序千万别倒过来先迁核心链路，从纯函数和数据转换开始最稳。

总结

四步是：黄金测试冻行为、语义差异表、按批迁移、灰度对拍。代码 迁移 语言 能不能成，不取决于 AI 翻译多快，取决于对照测试盖住多少真实请求。跨语言 代码 迁移 的两个教训：别一次翻完所有模块，别把 AI 写的不确定代码直接上线。灰度 5% 到 50% 再到 100%，两周后老服务下线，那 8600 行省了大约六成机械翻译时间。代码 迁移 测试 方案 提前写好，比事后补对拍省三倍时间。
