AI 代码 审查：PR 流程与误报处理

编程助手·更新于 2026-11-15·AI 代码 审查, 代码审查 机器人, 误报率, CodeRabbit, AI 代码审查 误报, 代码审查 机器人 配置

团队四个人，两周一个 release，PR 平均 420 行改动，人工 review 要排到第二天。我们用的是 GitHub 私有仓，CodeRabbit 走 GitHub App，Copilot Business 一人一月 19 美元，加起来比请一个兼职 review 便宜。上了双审之后，首轮平均报 6 条意见，合并前能拦下 2 个真问题。这篇写 AI 代码 审查 怎么接进 PR 流程、误报怎么压下去，配置可以直接抄。

PR 流程改四个动作

第一，PR 先开成 draft，等机器人跑完首轮再叫人，CodeRabbit 一般 1 到 3 分钟出评论，draft 阶段不打扰同事。第二，AI 意见分三级：必须改、建议改、风格类，前两级作者处理，风格类交给 ruff 和 eslint。第三，人工只看 AI 标红的和业务逻辑，review 时间从 40 分钟压到 15 分钟。第四，合并前用 Copilot 做第二轮，两个模型交叉，召回率比单跑高。PR 描述里我固定写三行：改了什么、影响哪个接口、怎么验证，机器人读完描述再拆 diff，误报会少一截。仓库 Settings 里的 Rules 进 Rulesets，勾选 Automatically request Copilot code review 即可；CodeRabbit 在根目录建 .coderabbit.yaml：language 设 zh-CN，reviews.profile 设 chill，auto_review 打开、drafts 关掉，path_filters 排除 **/*.lock、dist/、/*.sql，tools.ruff.enabled 设 true。这套 AI 代码 审查 流程跑了两周，评论噪音少了一半。

误报怎么处理

广告位（文章中部）AdSense / 广告联盟代码插入点 · 建议 728×90 / 移动端 320×100

AI 代码审查 误报 这块，首月 47 条评论里 12 条无效，占 26%，分三类。第一类是不懂业务，比如把已参数化的 SQL 报成注入，改法是在 path_instructions 里写清这个目录的参数来源。第二类是重复报，同一文件同一行被三条意见覆盖，用 path_filters 挡掉生成代码和迁移脚本。第三类是纯风格，chill 档加 formatter 之后基本消失。测试文件也单独交代一句：断言风格和 mock 方式写进指令，能再砍掉一部分噪音。动作固定成两句：确认无效就回 @coderabbitai resolve 关掉，拿不准的先留着；每条误报记进 ai-false-positive 标签的 issue。代码审查 机器人 配置 里最值钱的就是排除目录和指令文件，调完一个月，误报率从 26% 降到 9%。

三个坑

一是大 PR 别指望 AI。一次超过 600 行，评论能刷到 40 多条，关键问题反被淹，我现在超过 400 行就拆。二是别让机器人替人签字，分支保护里的 required approval 只能给人，安全、支付、权限三类改动必须人工过。三是 AI 代码审查 误报 不沉淀，团队两周后就会集体无视评论，变成墙纸；每月花半小时把高频误报写进 instructions，比换工具管用。上线顺序也有讲究，先让机器人在只读模式跑两周，统计清楚误报再开自动评论，团队接受度完全不同。另外私有仓先确认代码会不会被拿去训练，企业版可以关数据留存，走不通就换能自托管的 Qodo Merge。

总结

AI 代码 审查 的收益不在多抓几个 bug，在把 PR 等待时间从一天压到两小时，人只审红线和业务。流程是 draft 先跑、人工后审、合并前交叉二轮；误报靠配置和台账压到一成以下。机器人负责找可疑点，人负责判断能不能上线。代码审查 机器人 配置 改三处就够：语言、档位、排除目录。
